# Running Privacy-Aware Audio Learning

[Project overview](../README.md) · [Examples](examples.md) · [Research status](../docs/research-status.md)

Use `train_unified.py` as the single entrypoint. Active research modes are `normal`, `dp`, and `vib`; the `whisper_lora` CLI option remains for historical compatibility and is unmaintained.

## Install from the repository root

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python experiment/train_unified.py --help
```

On Windows, activate with `.venv\Scripts\activate`. For a CUDA environment, install a suitable PyTorch build for that machine before installing the core requirements. This update was tested on CPU on macOS, not CUDA.

## Dataset-free model self-check

```bash
python experiment/train_unified.py --smoke-test --feature_type opensmile --mode normal
python experiment/train_unified.py --smoke-test --feature_type opensmile --mode vib
python experiment/train_unified.py --smoke-test --feature_type mel --mode normal
python experiment/train_unified.py --smoke-test --feature_type mel --mode vib
```

This executes the existing model implementations with a smaller, one-layer configuration and synthetic padded feature sequences. It checks finite logits/loss/gradients, a real optimizer update, and evaluation output. It does not instantiate a real dataset, compute research metrics, test Monte Carlo evaluation, or validate DP. `--smoke-test --mode dp` is rejected explicitly.

The self-check always uses CPU and creates no checkpoints or training logs. `--help` and argument validation run before dependency imports. Failures return a nonzero process exit code.

## Real-data prerequisites

Real training resolves relative data paths from the working directory. Run it from `experiment/`:

```text
experiment/
  data/
    speaker_folds.csv                 # speaker_id, fold (five folds)
    all_expanded_features_fixed.csv   # historical OpenSMILE index / label source
    dataset.py                       # REQUIRED OpenSMILE loader; currently absent
  audio_mel/data-mel/
    mel_dataset.csv                  # feature_path, speaker_id
    mel_features/                    # numeric feature CSVs, 80 features per frame
```

`data/dataset.py` must provide `OpenSMILEAudioDataset` and `collate_fn_with_padding` for OpenSMILE training. It is not in this checkout; the synthetic self-check does not restore or exercise it. The historical `.gitignore` excludes `data/` and CSV files.

The MEL loader gets labels from the OpenSMILE index when available and otherwise guesses from speaker identifiers. Supply verified labels; see the [research-status notes](../docs/research-status.md) before interpreting results. Feature files and speaker folds must refer to the same identities.

Once the required files and preprocessing have been prepared:

```bash
cd experiment
python train_unified.py --feature_type mel --mode normal --epochs 10
python train_unified.py --feature_type mel --mode vib --z_dim 64 --beta 1e-3 --epochs 10
```

The trainer selects CUDA if available, otherwise CPU. It does not select Apple MPS. The entrypoint creates `checkpoints/` before training; logs are written under `logs/`.

## Configuration and results

| Option | Meaning |
|---|---|
| `--feature_type opensmile` / `mel` | Select feature-specific configuration |
| `--mode normal` / `dp` / `vib` | Select training method |
| `--epochs`, `--batch_size`, `--lr` | Override the corresponding settings |
| `--epsilon` | Encoder DP experiment target; not a full-model guarantee |
| `--z_dim`, `--beta`, `--mc_samples` | VIB latent dimension, regularization and sampling settings |

Real training uses the configured five-fold loop. The final-epoch metrics are summarized as **mean ± sample standard deviation (`ddof=1`)**. Existing mean keys remain in the returned dictionary; additional `<metric>_std` keys hold standard deviations. Accuracy/F1 and their standard deviations remain on the same 0–1 scale. No five-fold result has been generated by the synthetic checks.
